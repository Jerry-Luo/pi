速查：pi 启动三层映射

从 shell 敲下 pi 到控制流进入 main，中间只有三层文件。本表是 Lesson 0001 之前那段旅程的压缩版（版本锚 1.1.0）。

01执行顺序

shell 执行 bin/pi（符号链接 → dist/bundle/cli.js）
  │
  ├─ cli.js L4   enableCompileCache()          ← 必须先于大 bundle 加载
  ├─ cli.js L5   createRequire(...)("./cli-runtime.js")
  │
  ├─ cli-runtime L3  静态 import 的全部 chunk 先求值   ← 含 provider SDK 模块初始化
  ├─ cli-runtime L3  setupCli()  内联定义并执行
  │                    process.title / 两个 env 标记 / 静音 emitWarning / 初始 dispatcher
  └─ cli-runtime L3  main(process.argv.slice(2))  → 进入 main.ts

02三层对照表

层文件职责（每层一句话）
启动器 dist/bundle/cli.js:1–5 稳定极小入口：开 V8 编译缓存，再同步加载运行时。相对 import.meta.url 解析，任意 cwd / 符号链接下可用。
运行时 bundle dist/bundle/cli-runtime.js:1–3 esbuild 产物：L2 为注入 banner；L3 静态导入具名符号（main、configureHttpDispatcher、APP_NAME）与 ~14 个副作用 chunk，然后内联定义并执行 setupCli()，最后调用 main。
仓库源码 packages/coding-agent/src/cli.ts:1–6
packages/coding-agent/src/cli/setup.ts:1–13		 唯一值得学习的层：setupCli()（进程标识、环境标记、警告静音、初始 dispatcher）先行，main(argv) 随后。

03构建链（产物从哪来）

步骤出处结果
1. tsc 编译packages/coding-agent/package.json build:unbundleddist/cli.js（chmod +x，含 dist/rpc-entry.js）
2. esbuild 打包根 scripts/build-coding-agent-bundle.mjs:165–170以 dist/cli.js 为入口产出 dist/bundle/cli-runtime.js + splitting chunks
3. 写启动器同脚本 :253–259逐字写入 5 行 bundle/cli.js 并 chmod 0o755——与安装产物完全一致
两条铁律 ① esbuild chunk 文件名不是稳定边界（0.87.1 → 1.1.0 已三次全部更名）；② 仓库与安装 pi 版本不一致时，立即停止用安装产物验证行为，先对齐版本（LR-0002）。

# Mission: Pi 源码

## Why

深度理解 pi 编码代理的全链路架构（用户输入 → CLI → 会话编排 → Agent 循环 → 模型 Provider → TUI），并让这份理解同时服务四个现实出口：向上游贡献代码（A）、复用 `pi-agent-core`/`pi-ai` 自建代理（B）、在 pi 上构建扩展/主题/包（C）、为自研系统做架构评估（D）。用户已确认四个方向全部在目标内，不分先后；课程按既定 11 课大纲走深主链路，四方向在相应课时自然汇入。

## Success looks like

- **（已定锚点）用 pi 的 TypeScript SDK 搭出并跑通一个最小自建代理**：复用 agent/ai 两层、以自有（非 TUI）前端驱动，完成至少一轮"输入 → 工具调用 → 输出"。
- 不看资料画出一次用户输入的完整调用链（≥5 步），标出每步负责的包与关键函数。
- 拿到一个 pi 的 bug 报告或 feature 请求，能定位到正确的包/文件/函数，并说明改动波及哪些层。
- （方向 A）完成至少一个达到可提交上游质量的改动（通过测试与 `npm run check`）。

## Constraints

- 每次 60–90 分钟；中文教学与文档。
- 聊天讲解保持"沿调用链直讲、不主动提问"；巩固通过 HTML lesson 内的**可选小测验**完成（用户 2025 已确认）。
- 仓库与本地安装 pi 版本必须对齐；行号不跨版本沿用，符号先重定位。
- 不修改产品源码；不运行构建/测试，验证命令交用户执行。

## Out of scope

- `chord`、`telemetry`、`protocol`、`client`、`server`、`durable`、`env`、`evals` 等外围工作区（第 09 课前只做边界认识）。
- 各 LLM 厂商协议细节超出第 05 课所需范围。
- 为 pi 写真实扩展/贡献代码的实操——待主线（第 00–07 课）完成后按需移入。

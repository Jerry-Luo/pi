# Pi 源码学习

本目录是 Pi 单体仓库的可续学课程。目标不是通读文件，而是能解释一个用户输入如何经过 CLI、会话编排、Agent 循环、模型 Provider 与 TUI，并能安全定位后续改动。

## 从这里开始

1. 每次新会话先阅读本文件、`STUDY_STATE.md` 和 `RESUME_PROMPT.md`。
2. 在 `CURRICULUM.md` 找到 `STUDY_STATE.md` 的当前课时与当前项。
3. 开始阅读一个源码项**之前**，先在 `STUDY_STATE.md` 写入该项。这是预写检查点：会话突然中断时，下一会话从该项重新开始即可。
4. 读完一项后，立即勾选该项，并在状态文件留下 1–3 条已验证事实和下一项。较长的说明写入 `LEARNING_NOTES.md`。
5. 只在当前课时满足完成条件后移动到下一课。

## 学习方式

每个课时按同一节奏进行：

1. **场景**：导师先给出一个具体用户行为、涉及的模块和本课要解决的问题。
2. **讲解**：导师用源码路径和符号解释各层的责任、数据流和设计取舍；配置文件中的字段由导师归纳，不作为抄写题。
3. **定向阅读**：学习者只阅读能验证当前解释的一小段源码或测试；导师必须直接给出路径、最小完整源码和逐行说明，不能要求学习者自行寻找文件。优先使用 CodeGraph 的 `explore`、`callers`、`callees` 追踪关系。
4. **源码优先**：已安装产物只用于确认真实入口和构建结果，并应尽快映射回仓库源码。只要已安装包与仓库版本不一致，立即提醒学习者将两者更新到完全一致；对齐前以仓库源码学习，但暂停用安装产物验证仓库行为。
5. **直接讲解推理**：导师直接说明“下一步会发生什么”“职责为什么在这一层”及“替换这一层会影响什么”，给出因果链和边界结论，不把关键结论留作猜题。
6. **不主动提问**：导师只按调用链顺序逐步讲解，不设置检查题或要求学习者回答；学习者有疑问时主动提出。
7. **检查点**：导师将已验证事实、尚未理解的问题和下一项写入 `STUDY_STATE.md`。

讲解应覆盖因果、边界和调用链，不要求学习者复述 package manifest、类型字段或代码文本。每次建议 60–90 分钟；一个源码项读不完时，保持其为“进行中”，下一会话从该项的场景重新进入。

## 范围与顺序

Pi 有多个工作区。课程先聚焦产品主链路：

`packages/coding-agent → packages/agent → packages/ai → packages/tui`

`chord`、`telemetry`、`protocol`、`client`、`server` 等包在第 9 课才做边界学习。这样先获得一个可运行的心智模型，再扩展到独立基础设施。

## 恢复保证

课程通过版本可见的 Markdown 状态保存进度，而不是依赖聊天历史。只要在开始每个源码项前写入预写检查点，任意新会话都能确定下一步。若中断发生在未更新状态的几分钟内，重新阅读状态中标为“进行中”的源码项；重复阅读一个文件比跳过未知进度更可靠。

本目录不会自动运行命令、构建或测试。需要验证行为时，先由学习者确认并执行仓库规定的命令。
